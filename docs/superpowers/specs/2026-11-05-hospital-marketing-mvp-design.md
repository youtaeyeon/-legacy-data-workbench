# 병원 계약정보·마케팅 위키 MVP 설계

## 목적

영업부 공용 폴더의 엑셀에 기록된 병원 계약 정보를 읽어, 마케팅팀이 관리할 기본 정보·납품 장비·마케팅 물품·온라인 채널·제품 관련 콘텐츠를 한곳에서 누적 관리한다. 초기에는 기존 병원 전체 목업 목록을 가져오고, 이후 실행에서는 신규·변경 병원을 식별해 결과를 갱신한다. 결과는 병원별 Markdown 문서와 필터 가능한 단일 HTML 대시보드, 마케팅팀 엑셀로 제공한다.

## 왜 필요한가

현재 영업부가 신규 계약 병원을 공용 서버 엑셀에 기록한 뒤, 마케팅부가 병원 기본 정보를 자체 엑셀로 옮기고 납품 장비·마케팅 물품과 온라인 채널 조사 결과를 추가한다. 반복 입력과 별도 조사로 최신화 누락과 중복이 생길 수 있다. 과제에서는 실제 회사 자료에 접근하지 않고 목업 데이터로 이 흐름을 시연한다.

## 목표

- Windows에서 실행할 수 있는 데스크톱 EXE를 제공한다.
- 첫 실행 때 source 폴더와 target 폴더를 선택하고 설정을 재사용한다.
- source 폴더에서 사용자가 선택한 지원 확장자의 파일을 읽는다. 초기 적재 시 기존 병원 전체 목업 목록을 가져오고 모든 선택 원본을 Markdown 위키로 보존한다.
- 병원 ID를 기준으로 신규·변경·변경 없음 상태를 구분하고, 이름으로만 추측 매칭하지 않는다.
- 구조화된 기준 데이터는 target의 SQLite DB에 저장한다. Markdown은 DB에서 생성되는 읽기용 결과다.
- 병원별 Markdown, 검색·필터 가능한 단일 HTML 대시보드, 마케팅팀용 Excel 내보내기를 target에 만든다.
- 초기 전체 목록 가져오기와 두 번째 이후 증분 업데이트 시나리오를 목업 데이터로 검증한다.
- AI 제공자를 교체할 수 있는 공통 인터페이스와 설정 화면을 마련한다. 목업 모드에서는 외부 AI 호출 없이 재현 가능한 샘플 분류·문서 결과를 제공한다.
- AI API 키는 설정 파일에 평문으로 저장하지 않고 OS 자격 증명 저장소를 사용한다.
- 앱에서 읽을 원본 확장자를 선택할 수 있고, 폴더 설정/Source/Target/처리 구역 라벨은 검은색으로 표시한다.

## 비목표

- 회사 공용 서버에 실제 접속하거나 실제 회사 엑셀을 사용하는 것.
- 실제 웹 검색, SNS/YouTube API 연동 또는 병원 채널 자동 크롤링.
- 실제 병원·제품 데이터로 콘텐츠 관련성을 판정하는 것.
- 여러 사용자의 동시 편집, 중앙 웹서비스, 사내 인증·권한 관리.
- 자동으로 사람의 승인 없이 마케팅팀 운영 엑셀을 덮어쓰는 것.

## 사용자 흐름

1. 사용자가 EXE를 실행하고 source 폴더와 target 폴더를 지정한다.
2. source 폴더에 둔 목업 Excel 파일들을 읽는다. 초기 적재 시 전체 병원 목록을 가져온다.
3. 후속 실행에서 새 Excel 파일을 다시 읽고, 병원 ID로 기존 DB와 비교한다.
4. 새 병원은 추가하고, 기존 병원의 바뀐 필드는 변경 이력/처리 결과에 표시한다. 삭제는 자동 반영하지 않는다.
5. 목업 마케팅 보강 데이터에 있는 납품 장비, 마케팅 물품, 채널과 영상/게시물 후보를 병원에 연결한다.
6. 제품 관련성은 울트라클리어·리뉴비온·피아모 기준으로 목업 콘텐츠를 분류한다. 관련 콘텐츠만 결과에 포함하고, 무관한 콘텐츠는 제외하며 판단 상태를 보고서에 남긴다.
7. DB를 기준으로 Markdown, HTML 대시보드, Excel 내보내기를 생성한다.
8. 사용자는 대시보드에서 병원·제품·채널·관련 콘텐츠를 검색·필터링한다.

## 여러 원본 형식의 Markdown 위키 저장

첫 버전에서 사용자가 선택할 수 있는 입력 확장자는 `.xlsx`, `.csv`, `.docx`, `.pptx`, `.pdf`, `.txt`, `.md`, `.html`이다. 레거시 `.doc`/`.ppt` 및 이미지 PDF OCR은 범위 밖이다.

- 앱은 사용자가 선택한 확장자만 원본 폴더에서 읽는다. 확장자 선택은 설정에 저장되어 다음 실행에 유지된다.
- 선택된 모든 원본 파일은 텍스트/표/슬라이드 콘텐츠를 추출해 AI 제공자에 Markdown 문서화를 요청하고 `target/wiki/source-documents/` 아래에 원본 형식과 상대 경로를 반영해 저장한다.
- XLSX/CSV는 기존 병원·장비·마케팅 테이블의 정형 열이 식별되면 SQLite에 구조화해 반영하는 동시에 원본 위키 Markdown도 생성한다. DOCX/PPTX/PDF/TXT/MD/HTML은 문서 위키 Markdown으로 저장한다.
- DOCX는 문단과 표, PPTX는 슬라이드 텍스트와 표, PDF는 텍스트 레이어와 페이지 순서를 추출한다. HTML은 스크립트/스타일을 제외한 표시 텍스트를 추출한다.
- PDF OCR은 하지 않는다. 텍스트 레이어가 없는 PDF는 보고서에 명시하고 Markdown 변환하지 않는다.
- Mock 모드는 외부 AI 호출 없이 재현 가능한 Markdown 변환 결과를 만든다. 실제 제공자를 선택하면 선택된 파일의 추출 텍스트가 외부 제공자에 전송될 수 있으므로 과제에서는 목업 파일만 사용한다.
- 출력 파일명은 상대 경로와 확장자를 반영해 같은 이름의 서로 다른 원본이 덮어쓰지 않게 한다.
- 추출 불가, 비활성 확장자, 손상 파일은 import report에 기록하고 원본 파일은 수정하지 않는다.

## 목업 데이터와 필드

과제 저장소에 가상 병원만 포함한 입력 통합 문서와 마케팅 보강 자료를 제공한다. 병원명과 콘텐츠는 실재 기관·개인을 연상시키지 않는 명백한 가상 값으로 만든다.

- 병원 기본 정보: `hospital_id`(필수 고유키), `hospital_name`, `region`, `contract_date`, `source_updated_at`.
- 계약/납품 정보: `hospital_id`, `product_name`, `delivery_date`, `quantity`.
- 마케팅 물품: `hospital_id`, `product_name`, `material_name`, `quantity`, `status`.
- 채널: `hospital_id`, `platform`, `channel_name`, `url`.
- 콘텐츠 후보: `hospital_id`, `platform`, `title`, `url`, `description`, `published_at`, `matched_product`, `relevance_status`, `evidence`.
- 콘텐츠 제품 판별 기준 제품명: `울트라클리어`, `리뉴비온`, `피아모`.

입력 파일에 병원 ID가 없거나 중복이면 그 파일의 잘못된 행을 구체적으로 보고하고, 해당 행을 다른 병원에 임의 연결하지 않는다.

## 저장·출력 구조

사용자가 지정한 target 아래에 다음 구조를 만든다.

```text
target/
├── data/app.db                 # 기준 데이터, 처리 상태, 변경 이력
├── wiki/<hospital_id>.md       # 병원별 읽기용 문서
├── wiki/source-documents/       # 선택한 원본 확장자별 AI Markdown 문서
├── dashboard/index.html        # 검색·필터 가능한 단일 파일 대시보드
├── exports/marketing.xlsx      # 마케팅팀 전달용 내보내기
└── reports/last-import.json    # 가져오기 결과 및 오류 요약
```

- SQLite DB가 기준 저장소다. 기존 Markdown을 입력 데이터로 역비교하지 않는다.
- 같은 병원 ID는 같은 Markdown 경로를 재생성한다. 신규 ID는 새 문서를 만든다.
- 새 Excel 적용은 ID별 필드 비교 후 트랜잭션으로 저장한다. 오류가 난 파일은 성공한 것처럼 표시하지 않는다.
- 기존 데이터에서 사라진 병원은 삭제하지 않고 결과에 주의 항목으로만 표시한다.
- HTML은 외부 서버 없이 브라우저에서 열 수 있도록 필요한 데이터와 필터 로직을 포함한다. 공유는 HTML 파일 또는 target 폴더 공유로 한다.

## AI 제공자와 보안

- 내부 `AIProvider` 인터페이스로 콘텐츠 분류, 병원 요약, 원본 문서의 Markdown 변환을 제공하고 제공자별 adapter로 구현한다.
- 기본 제공자 선택지는 OpenAI, Anthropic, Google Gemini로 둔다. 제공자 추가는 공통 인터페이스에 adapter를 추가하는 구조로 제한한다.
- API 키를 OS credential manager에 저장하고 설정 화면에는 마스킹한다. 키를 로그·DB·Markdown·HTML·Excel에 기록하지 않는다.
- 과제의 기본 시연은 mock 모드이며 네트워크 요청 없이 동작한다. 실제 API 연결은 사용자가 제공자와 키를 설정한 경우에만 별도 시험한다.
- 목업 외 데이터를 사용하는 기능은 본 MVP 범위 밖이다. 회사 자료 전송 및 보안 검토는 과제 제출 후 별도 단계다.

## 첫 버전의 기술 방향 (설계 제안)

- Python 기반 Windows 데스크톱 앱: PySide6.
- Excel 읽기/쓰기: openpyxl; CSV/HTML/TXT/MD 파싱: Python 표준 라이브러리.
- DOCX/PPTX/PDF 텍스트 추출: python-docx, python-pptx, pypdf.
- 지속 저장: Python 표준 sqlite3.
- HTML 대시보드와 Markdown은 앱이 로컬 파일로 생성한다.
- API 자격 증명: keyring 추상화를 통해 Windows Credential Manager에 저장한다.
- Windows 패키징: PyInstaller. 코드 테스트는 먼저 WSL/Linux에서 수행하되, 최종 EXE는 Windows 환경에서 빌드·실행 검증한다.
- 이 프로젝트는 기존 코드베이스 없이 새로 시작한다. 따라서 기존 시스템 호환성은 첫 버전의 제약이 아니다.
- 이 기술 선택은 새 프로젝트를 위한 제안이다.

## 오류 및 데이터 안전

- 원본 Excel은 읽기 전용으로 취급하고 수정하지 않는다.
- 지원하지 않는 파일, 필수 열 누락, 중복 ID, 잘못된 날짜는 병원 ID/행 번호와 함께 import report에 기록한다.
- DOCX/PPTX/PDF 등의 텍스트 추출 오류와 비활성 확장자는 원본 파일명과 함께 import report에 기록한다. 이미지 PDF는 OCR하지 않는다.
- 부분 오류가 있으면 가져오기 결과에서 성공/실패 행 수를 구분한다. 지원되는 파일에 한해 정상 행의 import는 원자적 트랜잭션으로 기록한다.
- target DB와 결과 파일 생성 실패 시 원본 데이터를 수정하지 않는다.
- 새 엑셀에 없는 필드를 기존 값으로부터 임의 삭제하거나 덮어쓰지 않는다.

## 성공 기준

- 목업 전체 목록을 처음 적재하면 기대 병원 수와 ID가 DB 및 Markdown 문서 수에 일치한다.
- 두 번째 목업 파일에서 신규 ID는 추가되고, 변경 필드는 업데이트되며, 변경 없는 ID는 바뀌지 않는다.
- 중복/누락 ID 파일은 행을 잘못 매칭하지 않고 오류 리포트를 생성한다.
- 세 제품명 관련 목업 콘텐츠는 링크와 근거를 결과물에 포함하고, 무관 콘텐츠는 제외한다.
- 대시보드에서 병원·제품·플랫폼 필터가 동작하고, 결과물을 target 폴더에서 열 수 있다.
- 마케팅팀 Excel export에 기본 정보, 장비, 마케팅 물품, 채널, 관련 콘텐츠가 포함된다.
- 테스트는 목업만으로 네트워크 없이 재현 가능하며 API 키를 필요로 하지 않는다.
- 확장자 선택에 따라 지원 파일만 처리하고, 선택된 XLSX/CSV 및 DOCX/PPTX/PDF/TXT/MD/HTML 각각에 대응하는 source Markdown이 wiki에 생성된다.
- DOCX/PPTX 표·본문과 PDF 텍스트 레이어가 읽히고, 텍스트 없는 PDF는 오류 리포트로 남는다.
- 폴더 설정, Source/Target 라벨과 처리 구역 제목이 검은색으로 보인다.

## 구현자가 정할 세부 사항

- UI의 세부 배치, 검색·필터 표현, 오류 메시지 문구.
- 목업 통합 문서의 예시 레코드 값과 데이터량.
- AI 제공자별 모델 선택 UX와 API adapter의 세부 구현. 단, 기본 mock 모드와 비밀정보 처리 제약은 유지한다.
- HTML 대시보드의 시각적 표현과 Markdown 문서 템플릿.
